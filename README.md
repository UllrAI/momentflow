# MomentFlow · 拾光

让一次体验里属于你的照片和视频，自动汇成可以领取、保存或购买的个人回忆。

面向场馆、体验项目、营地及活动组织者的个人体验影像平台。覆盖游乐项目纪念片、活动个人相册、结营/研学合辑和幼儿园成长周记。

> 当前阶段：已提供可运行的交互 Demo，包含本地照片导入、真实照片短片生成、审核交付与模拟购买下载。场馆、人物、场次与价格均为演示数据；尚未接入真实识别、现场采集、生产账号体系或支付服务。

## 运行 Demo

```bash
cd demo
npm ci
npm run dev -- --port 4173
```

打开 http://localhost:4173 。推荐最新版 Chrome / Edge，照片仅在浏览器本地处理；刷新页面会恢复示例数据。

演示流程：**导入素材 → 核对场次与同行授权 → 打开工作室 → 编辑字幕/片段 → 生成预览 → 确认成片 → 交付 → 游客领取页 → 模拟解锁 → 下载视频**。

- 已实现：JPG/PNG/WebP 导入、场次与项目筛选、人工核对、片段排序/删除、字幕编辑、浏览器本地 720p 无声短片生成、取消生成、版本审核失效与重新确认、单场/批量交付、游客预览、模拟订单、视频与照片下载、重置演示。
- 仅模拟：场次/体验码关联、参与者身份与授权记录、订单及购买权益。
- 尚未实现：视频文件/监控流接入、自动人脸识别与聚类、跨镜头追踪、多模态事件分析、云端渲染存储、生产权限和真实支付。

详见 [Demo 使用与技术说明](demo/README.md)、[视觉与流程验收记录](demo/design-qa.md)。

## 从哪里开始

先验证一个起止明确、有拍摄授权的体验项目：体验码绑定场次和设备，采集照片/视频，生成纪念片，通过私密页面领取或购买。先跑通正确关联、成片、交付和异常恢复，再增加点位或行业。

已有幼儿园/营地渠道时，也可先验证周期合辑；不需要为了扩大定位而放弃已有客户优势。

## 两种生产模式

```mermaid
flowchart TD
    A[视频/照片与采集事件] --> B[场次与参与者关联]
    B --> C[固定体验：时间窗口与模板成片]
    B --> D[自由活动：候选事件与多模态整理]
    C --> E[权限核验与必要复核]
    D --> E
    E --> F[私密相册或纪念片预览]
    F --> G[免费领取/票内包含/付费解锁]
    G --> H[高清交付与恢复领取]
```

关联支持二维码、RFID、订单/场次、人工标记和授权的视觉匹配。人脸不是必填项，大模型也不是每段固定体验视频必须经过的实时步骤。素材匹配、账户认证、内容使用权和下载权益分别管理。

## 验证重点

最新研究将首批客户进一步限定为“已有拍摄素材、已有影像收费或明确交付义务、负责人可决策”的体验运营商；稳定期次的营地/研学机构作为第二条验证路径。国内已有低价人脸检索、找视频及快剪平台，不把基础功能当作已证明的竞争壁垒。

- 可服务体验中实际拍到多少，关联是否正确，未知/待核验是否被准确保留。
- 采集到可领取预览的端到端时延，峰值与断网情况下能否恢复。
- 实际预览、领取、实收购买、退款与高清交付，避免把游客数直接算成收入。
- 未售媒体、设备/现场服务、推理、渲染、存储和流量的完整成本。
- 参与者、同行、监护关系、拍摄用途及接收权限是否可执行、可修正、可撤回。

详细目标和演示商业计算均为待验证假设。竞品公开资料不等同于我们已经实现或已经证明的能力。
